## 1. 총평 및 판정

**판정: 구조적 위험. 현재 상태로는 배포할 수 없다(특히 정적 호스팅으로 공개하면 안 된다). 내부 사용도 C-1·C-2를 해결할 때까지 멈추기를 권고한다.**

3줄 요약
1. **지식베이스에 유출되면 안 되는 데이터가 들어 있고, 잘못 표시된 데이터도 섞여 있다.** 비공개 코호트 채널(메커톤 1·2회차 등) 글 약 170건이 `public/kb/qa.json`을 거쳐 `dist/kb/qa.json`에 포함됐다. 여기에는 "외부 무단 공유 금지"라고 적힌 교육 녹화본 Drive 링크, Claude 계정 지급용 구글폼 링크, 특정 참가자의 그룹ID·월드ID가 있다. 참가자가 쓴 글이 "[공식 답변]"이나 "공식 공지"로 표시된 사례도 확인했다.
2. **팩트체크가 확인하는 것은 "검색된 출처 12개 안에 비슷한 문장이 있느냐"뿐이다.** 출처의 권위·시점·적용 범위, 주장 누락, 부정어·숫자 뒤집힘은 막지 못한다. 그래서 지금(심사 기간) 가장 민감한 질문인 예시 1번 "심사 기간 중 월드 수정"에서 문제가 생긴다. 정정 전 정책 문장("제출 이후에도 업데이트 및 수정을 진행할 수 있습니다")은 크롤링 날짜 때문에 가장 최신 근거로 보이고, 이 문장을 근거로 한 답이 "✓ 팩트체크 통과"로 나갈 수 있다.
3. **검증 결과와 상관없이 "Discord 게시용 복사" 버튼이 항상 열려 있고, 답변은 공식 서포터 문체로 나온다.** 그래서 위 오류는 공식 입장처럼 그대로 게시될 수 있다. 단위 테스트는 LLM 응답을 고정해 놓고 돌리므로 이 중 어느 것도 증명하지 못한다.

배포 가능 여부의 근거
- 배포를 막는 사유(CRITICAL 2건)
  - C-1: 비공개·개인 데이터가 정적 파일로 배포된다.
  - C-2: 지금 진행 중인 심사 기간 규정에 대해 검증을 통과한 오답이 나올 수 있다.
- 재평가 조건: 7장 Top 5 중 1~3번을 끝내고 7.2의 회귀 평가셋을 통과하면, "2인 검토를 전제로 한 내부 파일럿" 여부를 다시 판단할 수 있다.

## 5. 정량 근거

### 5.1 인용문 퍼지 매칭 시뮬레이션 (factcheck.ts의 Dice ≥ 0.85, 정규화 = NFKC·소문자·공백/문장부호/기호 삭제)

| 사례 | 원문(정규화 길이) | 판정자 인용(오류) | 계산 | 결과 |
|---|---|---|---|---|
| 부정 반전 | "심사 기간에는 월드 정보를 수정할 수 없습니다" (19자) | "…수정할 수 **있**습니다" | 1자 치환, bigram 18개 중 2개 불일치 → 2·16/(18+18) = **0.889** | 통과 |
| 날짜 변조 | "모집 종료 시점은 10월 7일 02:00 UTC입니다" (22자) | "…10월 **17**일…" (23자) | 1자 삽입 → 2·20/(22+21) = **0.930** | 통과 |
| 가능↔불가능 | "공개 출시로 테스트하는 것은 가능합니다" (17자) | "…것은 **불**가능합니다" (18자) | 1자 삽입 → 2·15/(17+16) = **0.909** | 통과 |
| 기호 소거 | "1.5초", "-1", "40%", "≤ 100" | "15초", "1", "40", "≥ 100" | `[\s\p{P}\p{S}]` 전부 삭제 | 정확 일치로 처리 |
| 생략 이어붙이기 | 정정 공지("…심사 기간 중에는…", "(기존) 출품 완료 후에도 업데이트 가능") | "심사 기간 중에는 … 업데이트 가능" | 조각마다 존재 여부만 확인, 순서·문맥 무시 | 통과 |

일반식(근사, 반복 bigram 없음 가정): 길이 L인 조각에서 1자를 치환하면 Dice = (L−3)/(L−1)이다. 이 값이 0.85 이상이 되는 조건은 **L ≥ 15**다. 정규화 기준 15자 이상 인용이면 부정어나 숫자 1자 변경은 항상 원문 일치로 처리된다.

| X-2 | 정책 date=크롤링일 + "최신 날짜 우선" 프롬프트 + 오늘 날짜 없음 + 정책 페이지 미개정(C-2) → 검증기 supported | 진행 중인 심사 기간 규정을 반대로 안내 | 현재 유효 규정 고정 출처 + 날짜 주입 |
| X-3 | 비공개 자료가 KB에 있음(C-1) → 검색으로 출처에 포함 → 답변이 링크나 문구를 인용 → unknownLinks는 failed를 내지만 복사는 열려 있음(H-7) → 공개 채널 재게시 | 내부 사용만으로도 유출 | KB에서 제거(C-1) |
| X-4 | 질문 인젝션(M-3) → 검증 프롬프트에 그대로 전달 → 주장 선택적 추출(H-2) → verified → 복사 | 공격자가 원하는 문구가 공식 답변에 포함 | 문장-주장 매핑 강제(H-2) |
| X-5 | 출처 밖 공식 링크·사용자 정의 이름의 오탐(M-8) → "통과 아님"이 일상화 → 경고 무시 학습 → failed 답변 게시(H-7) | 검증 체계 형해화 | 오탐 줄이기 + 상태별 게이트 |
| X-6 | 공식 페르소나(H-5) + 감사 추적 없음(M-6) + 수집일만 표시(H-8) | 잘못된 공식 답변을 나중에 찾아 정정할 수 없음 | 실행 기록 + 게시 로그 |

### 7.2 배포 판단용 회귀 평가셋 (권고)

- 구성
  - 실제 문의 약 100건(익명화). 유형 18종을 비례 배분한다.

## 8. 실제로 확인한 것 vs 추정

**[확인] 파일·데이터에서 직접 확인**
- 2·3장에 인용한 모든 코드 줄 번호의 동작. 프롬프트에 오늘 날짜가 없다는 점 포함.
- `dist/kb/qa.json`에 Drive 녹화본 링크(17KSAj99…)와 "개발 그룹ID: 3Id4N"이 있다. dist/index.html:4에 CSP meta가 주입돼 있다.
- qa.json에 비공개 코호트 채널 문서와 공식 도메인 외 협업 링크가 있다(5.3 집계).
- 수집 원본의 role 오분류 사례와 그 사례가 qa.json에 반영된 것.
- 콘테스트 정책 원문의 "제출한 이후에도 업데이트 및 수정을 진행할 수 있습니다", 정책 modifiedAt이 크롤링 시각(2026-10-15T08:57:51Z)이라는 점.
- 2026-10-06 정정 공지(epoch 1791271882674에서 환산)와, 같은 날 상반된 공식 답변 문구.
- 5.1의 Dice 계산(코드 수식을 손으로 계산. 실행하지 않음).

**[추정] 정적 분석 기반 추론, 실행하지 않음**
- C-2·H-4 경로에서 실제 모델이 오답을 내는 빈도. 구조적으로 열려 있다는 것만 확인했다.
- 응답 지연(1~5분), 비용 금액(가격 가정), 브라우저 메모리(100~200MB).
- 경보 피로 정도(M-8), 공식 입장 오인 가능성(H-5).

**[미확인] 이번 감사에서 확인하지 못함**
- vitest 120개 통과, 커버리지 약 98%, tsc·빌드 통과: 셸 도구가 없어 다시 실행하지 못했다.
- 실제 API E2E 4건: 실행 기록을 찾지 못해 재현하지 못했다. 4건은 배포 판단의 통계적 근거로 부족하다.
- 앱의 실제 배포 형태(공개 호스팅인지 로컬 전용인지). C-1의 실제 노출 범위가 여기에 달려 있다.
- Discord 채널의 실제 권한 설정(채널명의 "비공개 채널(잠김)" 표기로 추론했다), 멘토 글의 공식 분류 여부, 브라우저 측 수집기의 판정 로직(저장소에 없음).
- `fallbacks:'default'`의 정확한 동작. 서드파티 SDK 릴리즈 노트로는 "안전 분류기 거절 시 권장 대체 모델로 재시도"이고 Anthropic 공식 문서는 확인하지 못했다.
- Opus 5.5·Sonnet 5.5 가격, Discord 약관의 현행 정확한 문구, 개인정보 관련 법률 판단.
